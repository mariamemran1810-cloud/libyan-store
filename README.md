# المتجر الليبي 🇱🇾

متجر إلكتروني عربي بالكامل، بأسعار بالدينار الليبي (د.ل)، مبني بـ **PHP 8 + SQLite**
بدون أي إطار خارجي — أي ملفات واضحة يمكنكِ فهمها وتعديلها بسهولة.

---

## 1) المتطلبات

| الأداة | الإصدار | ملاحظة |
|--------|---------|--------|
| PHP | 8.1 أو أحدث | مثبّت لديكِ (8.3) |
| إضافة pdo_sqlite | مضمّنة في PHP | لقاعدة البيانات |
| Git | لأي إصدار | للنسخ الاحتياطي |

> لا حاجة إلى MySQL ولا Composer ولا Node.js لتشغيل المشروع محليًا.

---

## 2) التشغيل محليًا (خطوة بخطوة)

1. افتحي سطر الأوامر (PowerShell) داخل مجلد المشروع:
   ```powershell
   cd "...\المشروع الافتراضي\libyan-store"
   ```
2. انشئي ملف الإعدادات من النموذج (مرة واحدة فقط):
   ```powershell
   Copy-Item .env.example .env
   ```
3. شغّل/ي الخادم المحلي:
   ```powershell
   php -S 127.0.0.1:8000 -t public public/index.php
   ```
4. افتحي المتصفح على العنوان: **http://127.0.0.1:8000**

للإيقاف: اضغطي `Ctrl + C` داخل نفس النافذة.

---

## 3) المفاتيح السرية

- لا تضع/ي أي كلمة مرور أو مفتاح داخل الكود — كل شيء يقرأ من **`.env`**.
- ملف `.env` موجود في `.gitignore` فلا يرفع إلى GitHub أبدًا.
- ولّدي/ي مفتاح التشفير وأضيف/يه في `.env`:
  ```powershell
  php -r "echo bin2hex(random_bytes(32));"
  ```
- أي شخص يحتاج نسخة تعمل: ينسخ `.env.example` إلى `.env`.

## 3.ب) قاعدة البيانات (المرحلة الثالثة)

أنشئي قاعدة البيانات وزرعي البيانات التجريبية (مرة واحدة):

```powershell
php scripts/migrate.php              # إنشاء الجداول + 6 أقسام + 20 منتجًا
php scripts/migrate.php --fresh      # بدء نظيف بالكامل (يحذف كل شيء!)
php scripts/reseed-demo.php         # تحديث الأقسام والمنتجات من الملفات (يحافظ على الحسابات)
```

| الدور | البريد | يُسمح له |

## 5) قواعد معمارية مهمة

1. **لا أسرار في الكود** — كل الإعدادات في `.env`.
2. **كل مدخل من المستخدم يمر على `Validate::check()`** قبل الحفظ.
3. **كل نموذج HTML يحتوي `Csrf::field()`** — وإلا يُرفض الطلب.
4. **كل استعلام قاعدة بيانات استعدادي (prepared)** — منع حقن SQL.
5. **كل نص يُعرض من مستخدم يمر على `e()`** — منع XSS.
6. **الأخطاء تُسجَّل** في `storage/logs/app.log` وتظهر بصفحة عربية مفهومة.

### الاختبار الذاتي (الكود)

```powershell
php docs/selftest.php
```

يتحقق من 75 نقطة: الإعدادات، التحقق من المدخلات، قاعدة البيانات، تشفير كلمات المرور،
السلة، خصم المخزون، تراجع المعاملات عند نقص المخزون، تقييد معدل الطلبات،
رسوم التوصيل حسب المدينة، مدة التحضير للمنتجات،

### اختبارات HTTP الكاملة (المرحلة السادسة)

```powershell
php docs/httptest.php
```

يشغّل **خادمًا مؤقتًا على منفذ مستقل** (لا يحتاج خادمك المفتوح) وينفّذ 98 سيناريوهًا
حقيقيًا بطلب HTTP كامل، ثم **ينظف كل بيانات الاختبار تلقائيًا**:

| المجموعة | ما يختبره |
|----------|-----------|
| الصفحات العامة | 200/404، RTL عربي، title/meta، h1 واحد، CSS، رؤوس الأمان |
| الحساب | تسجيل، بريد مكرر، دخول، حظر المحاولات، تغيير كلمة المرور |
| السلة والطلب | CSRF، تقييد المخزون، تحقق البيانات، رسوم التوصيل حسب المدينة، إنشاء الطلب، خصم المخزون، صفحة التأكيد، حظر الإغراق |
| الصلاحيات | زائرة/عميلة/بائعة/مسؤولة على كل مسار (302/403/200) |
| اللوحة | إنشاء وتعديل وحذف الأقسام والمنتجات، رفض حذف قسم فيه منتجات، تفاصيل الطلب، تغيير الحالة، حفظ إعدادات التوصيل واستعادتها |
| المنتجات | مدة التحضير تظهر للأطعمة ولا تظهر للملابس |
| الأمان | XSS مهرَّب، حقن SQL، قراءة .env، رفع PHP مزيّف، PNG صحيح، رؤوس أمنية، سجل بلا أخطاء PHP |
| SEO/النشر | robots.txt، sitemap.xml ديناميكي، /healthz، og:url، favicon، JSON-LD، ?v= للـ CSS |

### تنظيف بيانات الاختبار

```powershell
php scripts/cleanup-tests.php      # يحذف طلبات التجربة ويستعيد المخزون
php scripts/backup.php             # نسخة احتياطية لقاعدة البيانات والصور
```

### التجهيز للنشر (المرحلة السابعة)

الدليل الكامل خطوة بخطوة (cPanel و VPS و nginx و SSL): **[docs/deploy.md](docs/deploy.md)**

باختصار:

1. `APP_ENV=production` و `APP_DEBUG=false` و `APP_URL=https://نطاقك` في `.env`
2. ارفعي الملفات بحيث يكون `public/` فقط داخل الويب (باقي المجلدات خارجها)
3. `php scripts/migrate.php` + إنشاء حساب مسؤول بـ `--admin= --password=`
4. `/healthz` يجب أن يعرض `"status":"ok"`
5. جدولي `php scripts/backup.php`

ملفات جاهزة للنشر:
- `public/.htaccess` — ضغط، تخزين مؤقت، رؤوس أمان، حماية ملفات البداية
- `/sitemap.xml` ديناميكي + `/robots.txt` ديناميكي (يتبع `APP_URL`)
- `/healthz` فحص صحة للمراقبة
- `scripts/backup.php` نسخة احتياطية بالضغط الزمني
- أيقونة موقع + og:url + JSON-LD للمنتجات (SEO أفضل)

## المرحلة الرابعة: السلة وإتمام الطلب

1. الزائرة تضيف منتجًا إلى السلة (تُحفظ في الجلسة — تعمل حتى بدون حساب).
2. **لا يمكن تجاوز المخزون**: الكمية تُحدَّ تلقائيًا لعدد القطع المتوفرة.
3. صفحة السلة تسمح بتعديل الكميات أو حذف الأصناف.
4. إتمام الطلب: الاسم/الهاتف/المدينة/العنوان (مع تحقق من الصحة) — عربي بالكامل.
5. عند التأكيد يُنشأ الطلب **داخل معاملة واحدة**:
   - فحص المخزون لكل صنف
   - خصم الكميات من المخزون
   - حفظ بنود الطلب والإجمالي
   - إن فشل أي شيء **ترتجع القاعدة كما كانت** (لا طلب ناقص ولا مخزون سالب).
6. صفحة تأكيد برقم الطلب، تظهر لصاحب الطلب فقط (وإلا 404).
7. المسؤولة/البائعة تغيّران حالة الطلب من `/admin/orders`.
8. **حماية من الإرسال المتكرر**: 5 محاولات كحد أقصى كل دقيقة ثم يُطلب منك الانتظار.

## المرحلة الخامسة: لوحة الإدارة والصلاحيات

| الميزة | المسؤولة (admin) | البائعة (seller) | العميلة (customer) |
|--------|:-:|:-:|:-:|
| تصفح المتجر والشراء | ✅ | ✅ | ✅ |
| إدارة المنتجات | ✅ | ✅ | ❌ |
| عرض الطلبات وتغيير حالتها + تفاصيل الطلب | ✅ | ✅ | ❌ |
| إدارة الأقسام (إضافة/تعديل/حذف) | ✅ | ❌ 403 | ❌ 403 |
| إدارة المستخدمين وتغيير الأدوار | ✅ | ❌ 403 | ❌ 403 |
| تغيير كلمة المرور الخاصة بها | ✅ | ✅ | ✅ |

إضافات المرحلة الخامسة:

- **إدارة الأقسام** كاملة: إضافة/تعديل/حذف، مع **رفض حذف القسم إذا كان يحتوي منتجات**.
- **تفاصيل الطلب** `/admin/orders/{id}`: بيانات العميلة، ملاحظاتها، بنود الطلب، تغيير الحالة.
- **تغيير كلمة المرور** من `/account/password`: يتحقق من كلمة المرور الحالية،
  يرفض المطابقة، ثم **يسجّل الخروج ويطلب الدخول مجددًا** بكلمة المرور الجديدة.
- **تنبيه المخزون المنخفض** (5 أو أقل) بارز أعلى لوحة التحكم + بطاقة **إجمالي المبيعات**.
- **مقيّد معدل الطلبات** (`App\Core\Throttle`) لمنع الإرسال المتكرر.
